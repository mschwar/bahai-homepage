# Homepage Phase 0 Acceptance Gates

The audit is acceptable only if:

- every meaningful top-level file/directory and subsystem is classified with evidence;
- current production behavior is distinguished from experiments and roadmap-only ideas;
- Git history is used to explain *why* important decisions/subsystems exist;
- live/runtime/deployment/data dependencies are mapped;
- current product doctrine is reconstructed from behavior/history, not copied from the 2025 roadmap;
- the audit identifies exactly which modernization changes are high-leverage versus churn;
- future live-refactor and collection-abstraction streams have explicit seams/gates;
- the Ruhi memorization task is present but BLOCKED;
- no production code or configuration was modified;
- `HANDOFF.md` tells a human whether the repo is safe/ready for the next retrofit phase and what ambiguities remain.
